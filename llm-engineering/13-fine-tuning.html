# 微调 Fine-tuning

# 这篇解决什么问题

微调用于让模型学习特定风格、格式、领域表达或任务模式。它不是万能知识库，也不能替代 RAG 和工具调用。

# 什么时候考虑微调

# 输出格式长期不稳定

即使用 Prompt 和结构化输出约束，仍然难以稳定满足格式要求。

# 领域表达很固定

例如客服话术、质检标签、代码风格、行业术语。

# 大量同类样例

有足够高质量训练数据，并且任务边界稳定。

# 什么时候不该微调

# 知识经常变化

公司制度、商品库存、价格、订单状态更适合 RAG 或工具调用。

# 需要实时查询

实时事实应该走 API、数据库或搜索。

# 训练数据质量差

低质量数据会让模型学坏，后续排查更困难。

# 数据准备

# 样例格式

准备输入、期望输出、系统指令和必要上下文。

# 数据清洗

去重、脱敏、修正错误标签、统一风格。

# 数据划分

区分训练集、验证集、测试集，避免自我感觉良好。

# 评估与上线

# 离线评测

比较微调前后的准确率、格式稳定性、成本和延迟。

# 灰度发布

小流量验证，保留回滚机制。

# 持续迭代

把线上坏案例沉淀为新数据，但要人工审核。
